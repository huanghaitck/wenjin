# Historical Humanizer Zh

## 目标

把“人化”限定为历史学编辑工作：让材料、行动者和因果关系直接推动论证，减少可预测的模板结构，同时完整保留证据、限定和来源。不要把降低检测分数当作质量目标，也不要用随机口语、错别字、噪声或名家腔制造“人味”。

## 必读资源

执行任何改写前：

1. 阅读 [evidence-integrity.md](references/evidence-integrity.md)，建立保护清单。
2. 阅读 [historical-prose-operations.md](references/historical-prose-operations.md)，选择与稿件相符的史学操作。
3. 处理终审稿或 Phase 7 任务时，额外阅读 [phase7-protocol.md](references/phase7-protocol.md)。
4. 需要理解本技能与通用 Humanizer 的取舍时，阅读 [pattern-lineage.md](references/pattern-lineage.md)。
5. 若项目提供写作规范、术语表、证据包或作者认可范例，优先服从项目文件。
6. 用户要求按其长期写作习惯调优时，阅读 [memory-integration.md](references/memory-integration.md)，再从问津设置中已经配置、且由研究者授权的史学长期记忆库检索已批准偏好。
7. 用户提供连续多轮着色检测报告并要求据此返修时，阅读 [report-guided-revision.md](references/report-guided-revision.md)。检测报告只定位语言模式，不判定作者身份，也不替代原页、作者判断和保护检查。

## 决策门禁

先判断任务类型：

- `DIAGNOSE_ONLY`：用户只要求检查或尚未授权改稿。只列问题，不写入文件。
- `DRAFT_REVISION`：稿件仍处于写作阶段。允许语言与局部结构建议，但不得冒充事实终审。
- `AUDITED_COPY_REVISION`：稿件已通过事实和引用终审。只进行可逆的语言级修订。
- `SUBSTANTIVE_RETURN`：问题涉及新事实、论点、比较、引用或证据边界。停止人化，退回研究或写作阶段。

不得因为用户提到 AIGC 检测就默认重写。先说明检测器只能作为模式诊断，不能证明作者身份；把任务重新表述为提高历史学表达质量和可审计性。

## 硬约束

对终审稿执行以下零容忍规则：

1. 只处理副本，不覆盖终审基线。
2. 不新增、删除或改变事实命题、因果方向、时间顺序、论证层级和外推范围。
3. 不改变直接引文、项目译文、脚注标记、脚注正文、页码、档号、版本、书名、图题、图源、URL 或 DOI。
4. 不改变人名、地名、机构名、专门术语、转写、西里尔字母、日期、数量、单位或数字范围。
5. 不删除、挪用或强化“可能”“仅限于”“不足以”“不能据此”“尚无”“未见记录”等限定和阴性结果；“最有把握”“再进一步”“有些”“在此个案中”等证据层级或范围标记同样属于语义内容。
6. 不添加第一人称、情绪、反问、口语、意外发现或研究经历，除非原稿已有依据且投稿体例允许。
7. 不补造具体细节来替换抽象表达。
8. 可以从作者明确认可的多篇成熟史学论文中学习常见措辞、句式组织、段落节奏、转折方式和标点习惯；不得逐句复制、近似改写单一来源的独特表述，也不得复刻可识别的个人比喻或连续语段。
9. 不设固定“AI词每段上限”“噪声预算”或目标检测率。
10. 任一修改无法确定为纯语言变化时，标记 `MANUAL_REVIEW`，不要自行接受。

## 工作流程

### 1. 建立基线

记录输入文件、版本、字符数、脚注数、图表数和哈希。建立专名与术语表。对 Markdown 或纯文本修订，准备一份每行一个词的保护词表。

若存在个人写作画像，只把 `AUTHOR_APPROVED` 和 `STABLE_PROFILE` 当作默认偏好；`OBSERVED_ONCE` 只能生成待人工选择的候选，不得自动套用。

### 2. 诊断段落

逐段标记，而不是按词表机械改写：

- `H01_INTERNAL_PROCESS`：Phase、Agent、冻结、门禁、失败测试等内部工作语言进入正文。
- `H02_PREEMPTIVE_DEFENSE`：回应读者尚未提出的内部淘汰方向或预防性辩护。
- `H03_CONCEPT_BEFORE_EVIDENCE`：理论、定义或机制先出现，史实只是随后填格。
- `H04_EVIDENCE_LEDGER_PROSE`：正文像证据配置表、审计说明或项目报告。
- `H05_SYMMETRIC_LAYERS`：编号层级、三元或四元分类高度等长、等重。
- `H06_SUMMARY_CASCADE`：同一节连续出现多次回收、点题或结尾。
- `H07_APHORISTIC_CLAIM`：复杂关系被写成孤立格言或口号。
- `H08_QUOTE_NOT_WORKING`：引文之后没有解释动作、后果和推论边界。
- `H09_SOURCE_FLATTENING`：一手材料、直接研究、邻近研究和方法研究被当成同等证据。
- `H10_LIMIT_DRIFT`：语言简化导致限定词、阴性结果或不确定性弱化。
- `H11_ARTIFICIAL_VOICE`：为显得自然而加入无依据的“笔者认为”、反问、感受或口语。
- `H12_STYLE_COPYING`：逐句复制或近似改写单篇范文的独特语句；不包括从多篇范文归纳并复用学科通行的句式、节奏和措辞。
- `H13_PUNCTUATION_RHYTHM`：分号、冒号或排比被当成默认节奏，句间关系因标点过度分层而显得程序化。
- `H14_SYNOPTIC_GRID_PROSE`：一个段落压入多个年代、人物、任务和阶段变化，最后再用“集中—转疏—重组”之类的总括收束，读来像摘要、年表或提纲，而不是自然展开的历史叙述。

使用 `scripts/scan_historical_prose.py` 取得启发式提示。把输出视为线索，不视为 AIGC 判定。

### 3. 选择最小修订

优先按以下顺序处理：

1. 删除正文中的内部项目语言和不必要的预防性辩护。
2. 把地点、日期、人物、器物、动作或史料差异移到概念之前。
3. 把抽象名词主语改为有证据的行动者、材料或历史过程。
4. 让叙事与分析交替，避免连续数段只总结机制。
5. 把史料批判放在具体推论发生处，同时保留材料足以支持的判断。
6. 让比较材料检验一个最小共同问题，不为核心事件“增加票数”。
7. 让地点、载具、动物状态、昼夜、媒介或材料层变化承担过渡。
8. 每节只完成一次必要回收；其余判断嵌回最能承载它的史实段。
9. 保持核心术语稳定，不做同义词轮换。
10. 调整句长和段落节奏时服从论证轻重，不随机打乱。
11. 独立判断优先用句号收束；只有两个分句内部已有逗号且逻辑确属并列时才使用分号，不把分号当作罗列三层机制的默认工具。

### 4. 输出可审计结果

段落任务使用以下格式：

```text
STATUS: PASS_STYLE_ONLY | MANUAL_REVIEW | SUBSTANTIVE_RETURN
PARAGRAPH_ID:
RISK_TAGS:
REVISED_TEXT:
CHANGE_LOG:
INTEGRITY_CHECK:
```

文件任务另生成：

- 修订副本；
- 逐段 diff；
- `KEEP`、`REVISE`、拒绝和人工复核清单；
- 保护元素检查报告。

不得只交付一份无法追溯的“润色后全文”。

### 5. 验证

运行：

```powershell
python scripts/guard_historical_revision.py ORIGINAL REVISED --terms PROTECTED_TERMS.txt --json REPORT.json
```

要求所有精确保护类别为 `PASS`。再由人工检查语义保护项：事实、归因、因果、范围、限定和阴性结果。检测报告可以复测，但只能作为次要诊断；不得循环改写以追逐某个分数。

对全文任务，每批修订后运行一次 guard，合并全文后再运行一次。精确项目的数量和顺序通过，不代表限定词仍附着在原来的命题上：同一个“可能”可能在一处被误删、又在另一处被误加，自动检查仍会假通过。必须逐段对照限定词、范围词和证据层级标记所在的句子。

终审副本人化还必须由不参与改写的独立审计者复核。审计者只报告，不改稿；若审计失败，由改写者作最小修复、重建派生文件，再交独立审计。不得以主改写者自己的“通过”结论替代这一步。

## 通过标准

仅在同时满足以下条件时标记 `PASS_STYLE_ONLY`：

- 史实、论点、引文、脚注和限定均未改变；
- 每项修改可以说明具体的历史学表达功能；
- 稿件不依赖内部流程语言；
- 概念由材料推出而非替代材料；
- 没有引入假装个人化的口语或名家模仿；
- diff、保护元素检查和逐段决策表均已完成；
- 对终审副本，独立审计已经通过。

任何一项不满足，保持基线文本并转入 `MANUAL_REVIEW` 或 `SUBSTANTIVE_RETURN`。
