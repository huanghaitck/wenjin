# Phase 7 受控语言返修协议

## 目录

1. 进入条件
2. 基线冻结
3. 试运行
4. 全文处理
5. 差异与证据复核
6. 独立审计与返修闭环
7. 文档验收
8. 停止门禁

## 1. 进入条件

只有事实和引用终审已经通过、用户明确授权 Phase 7 时才进入。若项目权威流程另有规定，优先服从项目流程。

Phase 7 不补研究、不增引用、不改论点。发现实质问题时退回相应阶段，不在语言返修中偷偷修补。

## 2. 基线冻结

1. 记录终审稿路径、时间、SHA-256、字符数、脚注数、图表数。
2. 复制为 Humanizer 输入副本；保持终审稿只读。
3. 建立 P0 精确保护清单和 P1 语义保护清单。
4. 保存检测报告作为诊断材料，但不把其分数写成验收目标。

## 3. 试运行

先选择6至8个不同类型段落：

- 引言问题段；
- 学术史段；
- 一手材料及其解释段；
- 机制分析段；
- 比较或反证段；
- 结语段。

逐段输出风险标签、候选修订、变更说明和完整性检查。未经人工批准，不把试改扩展到全文。

## 4. 全文处理

按章节逐批处理，每批完成后立即 diff 并运行精确保护检查。建立逐段决策表，至少区分 `KEEP`、`REVISE`、`MANUAL_REVIEW` 和 `REJECT`。对已经自然、证据充分的段落标记 `KEEP`，不要为了覆盖率而强行改动；“全文处理完毕”不等于“每段都必须改变”。

维持项目规定的最低篇幅、章节功能、脚注和图表。不要以缩写为默认目标。

## 5. 差异与证据复核

1. 运行 `guard_historical_revision.py`。
2. 逐段审查所有 diff。
3. 把修改分为 `STYLE_ONLY`、`MANUAL_REVIEW`、`REJECT`。
4. 对任何事实、归因、因果、范围或限定变化恢复原文。
5. 对改变脚注锚点、引文或专名的修改直接拒绝。
6. 对接受的段落做术语一致性和引用可追溯性复核。
7. 全文合并后再次运行 guard，不能用各章节分别通过替代全文检查。
8. 对每个重复出现的限定词，检查它仍附着于原来的命题。计数和字面顺序无法识别“一处误删、另一处误加”的假通过。
9. 删除“第一层／第二层／第三层”等标签时，须保留原有证据等级；不得把“最有把握—再进一步—只能在直接叙述处确认”压成同一强度。

可以在此后复测 AIGC 报告。若作者提供连续报告，可按 [report-guided-revision.md](report-guided-revision.md) 有界定位持续出现的语言问题，但不得围绕分数无界重写全文。若检测分数和人工历史学判断冲突，以证据保真、可读性和投稿规范为准。

## 6. 独立审计与返修闭环

终审副本的主改写者不得兼任最终审计者。另设只读独立审计：

1. 先对照冻结基线与候选稿复核全部 `REVISE` 段落，不以主改写者的“通过”意见代替判断。
2. 检查事实、归因、行动顺序、因果、范围、限定、证据等级、引文、脚注和术语。
3. 独立运行全文 guard，并核验候选文件身份。
4. 审计者只写报告，不直接改稿。
5. 若为 `FAIL`，由改写者按报告作最小修复，重新生成 diff、DOCX 和校样，再交独立审计。
6. 只有明确的 `INDEPENDENT_AUDIT_PASS` 才能关闭 Phase 7 审计门禁。

## 7. 文档验收

重建 DOCX 后检查：

- Markdown 正文块与 Word 正文逐段一致，脚注锚点位置也一致；
- 真实脚注数量及页下注格式；
- 图表数量、题注、来源和清晰度；
- 标题、摘要、关键词和正文样式；
- 多语种字符、页码和换页；
- 字符数和章节完整性。

同时确认冻结的脚注正文、样式、设置和媒体文件没有被正文重建意外改变。使用项目指定的 LibreOffice 可执行文件；若命令不可直接调用，定位 `soffice.exe` 后以独立配置目录渲染。逐页检查 PDF 或页面图，返修影响到的页面必须重新检查。

## 8. 停止门禁

Phase 7 完成后只交付：

- 终审基线；
- 人化候选稿；
- diff；
- 保护元素报告；
- 独立审计及必要的复审报告；
- 渲染校样；
- 人工定稿清单。

最终文本由作者人工确认。不得自动宣称“已经无法检测”或“可以直接投稿”。
