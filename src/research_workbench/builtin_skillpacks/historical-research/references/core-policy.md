# 核心政策

## 适用边界

仅在“历史对象”与“史学操作”同时出现时隐式启用。历史对象包括过去的行动者、事件、制度、文本、档案、物质遗存和历史著作；史学操作包括史料阅读、史源批判、历史语境、学术史、解释、论证、引注和历史论文修订。

默认排除 Git 历史、浏览历史、软件日志、普通编程、当前新闻、商业调研、历史小说、通用翻译和一般文字润色。路径或文件名包含 `history` 不构成触发条件。

## 双模式

- 模块模式是默认：只执行当前请求所需的最小技能组合，不自动建项目、不启动多 Agent、不批量写入。
- 项目模式必须由用户明确启动，或在既有项目停止门禁上明确批准下一阶段。
- 上游阶段完成不自动授权下游阶段。

## 高成本动作

以下动作必须获得明确授权：启动完整项目、多 Agent、批量下载或导入、扫描新目录、更新长期记忆、冻结证据包、写完整论文、语言人化、投稿与最终定稿。

## 材料状态

按顺序区分：

`DISCOVERED → ACQUIRED_UNVERIFIED → FILE_VERIFIED → METADATA_READ → TARGETED_READ → FULL_READ → PAGE_VERIFIED → CITABLE`

文件存在、OCR 命中、目录记录或二手转引均不等于全文已读或可直接引用。OCR 是检索辅助；承担关键事实的扫描页必须回到图像核验。

## 网络与取得

- 联网检索是史学材料发现的核心能力，但网络入口必须分为开放 API、公开网页、学术索引和受限数据库。
- 发现记录、来源对象、证据单元和主张关系是不同对象；搜索结果不能直接进入正文。
- 公开全文应在授权目录实际保存并验收。没有公开全文时，登记完整题录、相关性、访问限制和用户动作，不得伪造取得状态。
- 不批量抓取明确禁止自动访问的服务，不绕过登录、付费、验证码、机构权限或保护阅读器。
- 不要求用户在对话或项目文件中提交密码。需要认证时使用用户控制的浏览器会话或服务的正式授权机制。
- 检索和取得规则见 [来源提供者政策](source-provider-policy.md)，证据对象见 [史学证据契约](evidence-contract.md)。

## 证据边界

- 区分材料记载、材料作者解释、当前研究者推论、竞争解释与尚不可知。
- 同源译本、OCR、摘录和重印不重复计为独立见证。
- 目录、摘要和二手转引不得冒充已见原件。
- 关键事实必须能回到原页、原书页、档号或稳定数字对象。
- 阴性结果必须记录检索范围和停止条件，不得写成绝对不存在。

## Agent 与模型

- 多 Agent 只用于独立、可并行、以只读为主的材料家族阅读、分语种检索、竞争解释、专项评审和引用复核。
- 同一正文、中央证据账本、唯一方向决定和正式长稿只能由一个主 Work 或唯一写作主体处理。
- 默认继承当前模型。Agent 可以提出能力升级理由，但不得静默切换模型或供应商。
- 推荐能力档位：`FAST_READING`、`DEEP_REASONING`、`VISION_OCR`、`CITATION_AUDIT`、`DOCUMENT_QA`。

## 记忆与隐私

插件默认 `memory_backend: none`。只有用户明确授权并配置后，才能调用 Obsidian、Zotero 或私人材料库。不得把私人全文、密码、Cookie、密钥或完整会话写入公共插件或长期记忆。

专业领域规则按 [领域 Profile Pack 规范](domain-profile-packs.md) 按需加载。私人作者画像、手改对照和受版权保护的训练语料不得进入公共 Profile Pack。

## 完成报告

清楚区分：已完成、已验证、未验证、失败或阴性结果、需要人工决定的下一门禁。不得把计划中的工作写成已经完成。
