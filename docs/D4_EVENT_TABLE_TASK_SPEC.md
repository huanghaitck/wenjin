# D4 Task Spec｜字段级锚定的逐事件比较表

状态：最小闭环已实现并通过真实项目 GUI 验收  
日期：2026-08-11

## 1. 研究问题

研究者心中的正式目标、核心时间窗、比较单位、材料层级和停止条件，先作为版本化研究计划保存。
Agent 可以独立构思，也可以按共同批准版执行，但不能把第一次回答当成正式计划。计划稳定后，核心
旅行材料需要被拆成可比较的事件行；阅读札记、OCR 命中和旧 Demo 证据不能代替这一步。

这里的“研究者意图”不是心理画像，而是研究者已在旧对话、研究计划和纠偏中外化出来的方向。
系统按“明确决定—恢复的上下文—待确认推断”标记其认识地位，并保留版本。Agent 的方案与该基线
比较后显示扩大、缩窄和遗漏；人工修正生成新版本而不静默覆盖旧决定。该基线约束研究任务，但绝不
替代原页和冻结证据。

## 2. 最小事件对象

每行保存：个案、日期、起讫地、路线、移动时间、原载与换算距离、调查对象、记录技术、中国参与者、
机构任务、原文、译文、缺失原因和备注。事件同时固定来源、精确版本、物理页、印刷页和文本块。

日期、地点、路线、距离、调查对象、记录技术、参与者、任务、原文和译文属于来源性字段。只要非空，
就必须分别声明 `field_anchors`；一个字段不能借用未列入事件的相邻页或相邻块。换算、缺失原因和研究
备注属于解释性字段，不伪装成原文事实。

## 3. 人工门禁

- Agent 只能创建 `draft` 候选，每批 1—20 行；
- 所引块必须属于同一来源，并按物理页和块序排列；
- 批准前，每个所引块须经人工核验，页面至少经人工抽查；
- 原文必须逐字存在于原文字段所锚定的已核块，不能把断词、软连字符或拼写规范化后仍称为原文；
- 人工可以在界面中修改字段，但修改仍受原锚点范围约束；需要新块时应拒绝旧候选并重新提交；
- 拒绝记录保留，不覆盖模型原提案；
- 已批准事件仍是 `PAGE_LINKED_EVENT_NOT_FROZEN`，不能直接供正式写作使用。

## 4. 真实验收

在秦岭项目中，DeepSeek 首次把 B009 的日期和 B010 的地点写入字段，却只引用 B006—B008。模拟
研究者据此拒绝候选，并把字段级锚点加入 harness。第二次候选只引用已核 B007，但模型把软连字符
规范化后仍声称逐字一致，批准门禁再次拒绝。最后从程序原页文本框复制 B007 精确文本，人工批准成功。

该过程证明的不是模型“最终答对”，而是研究者可以感知偏差、在程序内纠偏，并由审计链保存原提案、
拒绝理由、人工修订和最终决定。

第二轮真实验收覆盖李希霍芬物理页251—253。原书把连续观察标为 `24-/25. Jan.`，有效边界共有13个
文本块并止于下一条 `26. Januar.` 之前。实际操作暴露并修复了八项问题：任意12块上限、错误页标导致
整轮失败、模型动作JSON不能同轮重试、显式来源下的短块号被拒绝、DeepSeek两种动作包装被误作正文、
人工修页后候选原文不能显式回填，以及两处局部文本抽取错误。模拟历史学者逐页核对、修正文本、确认
两条跨页关系后，在客户端批准事件 `EVT_c05991d5c1714c728c54f0ae607fc95c`。其资格仍为
`PAGE_LINKED_EVENT_NOT_FROZEN`。完整环境检查、98项测试和前端语法检查均已通过。
