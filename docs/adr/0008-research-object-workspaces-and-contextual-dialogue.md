# ADR 0008｜Research Object Workspaces and Contextual Dialogue

状态：Accepted；D3 Demo implementation authorized
日期：2026-08-10

## 背景

D1/D2 为了快速验证闭环，把研究对话、图书馆、文献修复、文件导入、文章编辑和浏览器入口并列在
顶层。功能可以运行，但“研究对象”和“操作工具”混在同一层：文献修复看起来像独立产品，PDF
导入占据全局顶栏，文章工作台以 Markdown 文本框替代正式文档编辑，研究浏览器则被压缩成侧栏。

产品目标是辅助历史研究全过程，但历史研究并非固定流水线。问题、检索、阅读、来源批判、证据、
解释、写作和评审之间允许有记录的回退；系统必须保存研究者当时看到的对象版本和作出的决定。

## 决定一：永久入口只代表稳定工作空间

客户端保留四个永久入口：

1. **研究对话**：默认首页，项目线程、目标和研究讨论；
2. **研究图书馆**：收件箱、作品、版本、文件、页面处理和文献修复；
3. **文章工作台**：结构化稿件编辑、讨论、证据、引用、修订和导出；
4. **项目设置**：模型角色、Skills、数据库连接、权限、备份和项目配置。

中央区域使用研究对象标签页，可同时打开对话、文献、原页、稿件和浏览器。原页复核、文献修复、
证据卡、期刊模板和模型配置不再作为顶层产品入口。

## 决定二：导入与修复归入图书馆，但处理结果绑定精确文件版本

所有本地文件、文件夹盘点、Zotero 条目、公开网址和浏览器下载先进入图书馆收件箱。对话拖放只是
收件箱的快捷入口。用户明确选择：

- 加入工作区图书馆，可供多个本地项目引用；
- 作为项目私有材料登记，不出现在其他项目的默认检索中。

文献修复在具体文献的详情页中出现。其领域对象是 `FileVersion` 的 `DocumentProcessingRevision`，
而不是某个项目的临时 UI 状态。页面文本、物理页、印刷页候选、块区域、跨页关系、异常、OCR
提案和人工修订可以跨项目复用；相关性、阅读状态、来源资格、Evidence、Claim 和 Freeze 仍属于
具体项目。

若不同项目对同一页提出冲突修订，系统保留分支和来源，不静默覆盖；只有人工选择的处理修订成为
该文件版本的当前可用表示。

## 决定三：稿件内部使用结构化文档模型

文章工作台提供科研写作所需的 Word 类体验，但不复刻 Microsoft Word 全部功能。内部真相是带稳定
节点 ID 的结构化文档树，至少表达：

- 章节、段落、列表、表格、图像和标题层级；
- 脚注、文献引用和书目键；
- 批注、修订提案、接受/拒绝和版本；
- Claim/Evidence 回链和来源页锚点；
- 样式语义与有限页面设置。

DOCX 和 Markdown 都是文章工作台内的导入/导出适配器：DOCX 用于与 Word 和投稿流程交换，
Markdown 用于开放文本、Agent、Git 和可移植导出。复杂 DOCX 往返可能有损，导入和导出必须生成
fidelity report，不能把成功打开等同于格式完全保真。

页面感知来源 Markdown 与稿件文档模型是两类对象，不共用同一“Markdown 即真相”的假设。

## 决定四：文章工作台使用上下文研究对话侧栏

文章工作台右侧提供可折叠的研究侧栏，标签包括：

- 研究对话；
- 证据与主张；
- 引用与脚注；
- 批注与修订；
- 审批与版本。

侧栏仍由项目的唯一主 Agent 协调，不创建失去项目记忆的独立写作人格。每条上下文消息保存：

- `thread_id`；
- 当前 `manuscript_id`、文档版本和 `section_id`；
- 选区节点 ID、选区文本哈希和必要的快照；
- 明确附加的 Claim、Evidence、Source Page 或 Browser Receipt；
- 实际模型角色和工具结果。

灵感讨论默认只留在对话。把讨论提升为研究问题、主张、札记、写作提案或记忆候选必须由用户
显式决定；聊天内容不能静默进入论文正文。

## 决定五：浏览器是中央研究对象，控制与收集位于侧栏

研究网页和登录数据库需要完整中央空间。浏览器作为中央标签页打开；右侧栏显示检索计划、允许
域名、操作范围、结果收集篮、下载、引用回执和审批。对话可以收缩到侧栏或与浏览器分屏，但网页
本身不放进狭窄侧栏。

浏览器取得的网页和文件先进入图书馆收件箱，不能直接成为 Evidence。公开资源可有界获取；授权
数据库只能在用户已有合法访问权内操作，不绕过许可证、付费墙、验证码或访问控制。网页文本是
不可信输入，不能扩大 Agent 权限或修改项目 Goal。

## 决定六：全过程是可回退研究循环

```text
问题与范围 -> 检索 -> 收件箱与验收 -> 阅读与来源批判 -> 证据与解释 -> 写作与评审
     ^           |            |                    |                 |
     +-----------+------------+--------------------+-----------------+
                 所有回退产生对象、版本、票据或决定，不覆盖历史
```

系统辅助全过程，但不替教授决定史料真实性、解释强度、研究贡献和投稿判断。

## 后果

- 下一阶段先改信息架构和对象归属，再增加数据库数量；
- 现有 D1/D2 API 和数据必须通过迁移适配器继续可读；
- 图书馆将承担文件版本的共享页面处理表示，项目保留研究判断；
- 文章编辑器从 Markdown 文本框演进为结构化文档树；
- 研究对话成为跨工作空间的统一协调层，但上下文必须版本化；
- 用户已于 2026-08-10 批准迁移方案并授权 D3 Demo 实施；真实跨库处理记录迁移仍需单独验收。
