# ADR 0013：信息、项目知识、Agent 过程与长期记忆分层

状态：Accepted
日期：2026-08-12

## 背景

研究工作台同时保存本地书目、项目材料、对话、检索、证据、稿件和可复用判断。如果把这些对象统一称为“知识库”或把所有运行结果自动写入长期记忆，Agent 会逐渐混淆线索、史料、作者决定和模型推断，也会造成重复、过期与隐私风险。

## 决定

V1 固定四层：

1. **研究图书馆**：独立 `library.sqlite3`，保存 work/edition/file/file_version、标签和位置；跨项目复用，不承载项目论点。
2. **项目知识**：每项目独立数据库，保存研究设计、来源处理修订、逐事件表、证据、主张、冻结、稿件和评审；人工批准对象是当前研究事实。
3. **Agent 工作过程**：线程、消息、Run、工具事件、审批、检索结果和浏览器回执；用于恢复与审计，默认不得作为知识或证据。
4. **长期记忆候选**：项目内 `memory_candidates`；创建必须有类别、内容和稳定来源引用，人工批准后状态仅为 `approved_local`，不自动写入外部长期记忆。

`historical-memory` 和 `codex-memory` 适配器不在当前 Demo 中自动启用。未来接入时必须增加第二次明确提升、目标库选择、写入收据和撤销/废弃机制；不得把 `approved_local` 解释为已经写入外部记忆。

## 提升规则

可成为候选：已验证且跨会话或跨项目有复用价值的史学判断、阴性结果、方法、术语/地名关系、作者批准偏好和多样本文风画像。

不得自动成为候选：聊天全文、网页结果、OCR 草稿、翻译草稿、模型推断、被拒绝方案、临时工具输出、密码和登录状态。

外部检索结果必须先取得并验收来源；项目证据必须核回原页；长期记忆不得成为绕过来源资格的第二证据库。

## 界面约束

“记忆候选”页面必须显示四层说明和“不自动写入外部长期记忆库”。批准按钮使用“批准留在本项目候选区”，避免用户误以为已经全局同步。

## 结果

优点：减少信息污染；项目事实、运行记录和长期复用判断边界清楚；默认隐私风险低。

代价：同一内容可能先存在项目知识，再以短卡片形式成为记忆候选；外部记忆同步需要额外人工步骤。该重复是受控摘要和来源回链，不是复制整个项目。
