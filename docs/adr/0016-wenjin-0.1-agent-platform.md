# ADR 0016：问津 0.1 的 Agent 平台边界

- 状态：Accepted
- 日期：2026-08-15

## 决策

产品对外名称改为“问津｜人文社会科学研究工作台”。Python 包名、SQLite 标识和 Tauri identifier 在 0.1 中保持不变，以保证既有研究项目可直接升级。

0.1 采用“一个本地核心，多种客户端”的结构：网页、Windows 桌面、CLI 和 MCP 服务端共享同一套 Python 领域服务。桌面壳不得复制研究逻辑，只负责启动、诊断、文件选择、Word 桥接和显示本地网页。

### Agent 运行时

1. 主模型负责对话、工具循环和最终答复。
2. 辅助模型按任务分配，0.1 至少包括视觉/OCR、翻译、联网材料整理、上下文压缩和交叉评审；“自动”表示复用主模型。
3. 模型配置以可复用的“模型档案”为单位，角色只保存档案引用。支持 Ollama 和任意 OpenAI 兼容接口；提供商快捷项只是表单预设，不制造专有适配器。
4. MoA 是可选的虚拟主模型：参考模型先给出不带工具的意见，聚合模型仍是唯一能够调用工具和给出正式答复的主体。参考模型失败不得中止聚合模型；默认每个用户回合只扇出一次。
5. Agent 人格分成不可编辑的 Harness 宪法与可编辑、版本化的研究人格。研究人格可以规定称谓、学科取向、表达偏好和主动程度，但不得覆盖来源资格、证据冻结、写入审批和隐私边界。

### 图书馆、知识与记忆

1. 图书馆继续以作品、版本、文件和文件版本分层，支持书架、标签、全文检索、后台盘点和项目关联。
2. 0.1 的知识图谱只保存可回链的实体与关系建议；任何关系都必须指向作品、来源页、证据或人工研究札记，不从向量相似度直接宣告历史事实。
3. 信息、项目知识、Agent 运行状态、长期记忆四层在界面中分别展示。长期记忆仅保存人工批准的候选，不自动吸收完整对话、模型草稿或未核来源。

### 工具与扩展

1. Skills 使用版本化 `SKILL.md`，支持显式 `/skill-name` 调用和按动作筛选。
2. MCP 同时支持两种方向：问津可作为只读研究 MCP 服务端被其他客户端调用；外部 MCP 客户端接入采用显式配置、按需发现和逐次权限判断。
3. 浏览器与电脑操作必须是用户可见会话。登录、验证码、付费许可和最终下载由用户决定；Agent 可以在获准范围内检索、导航、填写和收集回执。
4. CLI 是正式客户端，不是调试残留；重要配置、诊断、图书馆检索、Agent 对话和 MCP 服务均需有 CLI 入口。

### 写作工作台

写作界面以结构化稿件为中心，提供阅读模式、缩放、章节导航、精确选区、完整表格编辑、版本差异和新版本保存。Word 桥接用于最终版式处理，但不能替代工作台内的基本阅读和修改能力。

### 中英界面

客户端界面提供中文和英文切换。研究材料、项目名称和用户文本保持原文；界面语言切换不改写数据。

## 借鉴与许可

- Hermes Agent：主模型/辅助任务、MoA 作为虚拟提供商、可编辑 Soul 的交互经验。
- pi-mono：模型 API、Agent loop、工具状态与客户端界面解耦。
- OpenAI Codex：App Server 式多客户端核心、线程事件、Skills、MCP 与审批模型。
- MCP 官方规范：Prompts、Resources、Tools 的控制边界。

只复用许可证清楚且确有必要的代码；直接复用必须记录上游版本、许可证和本地改动。仅借鉴设计时也在 `THIRD_PARTY_NOTICES.md` 说明来源。

## 0.1 验收

1. 全新安装可启动；侧车缺失依赖时给出可操作诊断。
2. 首次启动三步内可找到模型档案、角色分配、连接测试和 MoA。
3. 大目录盘点不阻塞界面，图书馆可分类、检索、移动书架并关联项目。
4. 研究人格、四层记忆、Skills 和 MCP 状态可见且边界清楚。
5. 浏览器、文章选区修改、版本保存和 Word 导出至少各完成一次真实操作。
6. CLI 与 MCP inspector 可调用核心只读研究能力。
7. 中文/英文界面可切换；版本页显示 0.1.0、构建号、schema 和组件健康状态。
