# ADR 0012：版本化史学技能与多画像文风学习

## 状态

已接受，2026-08-12。

## 背景

工作台已有通用润色和单次写作提案，但它不能区分史学语言返修、作者偏好与具体学者模仿，也没有复用本机 `historical-research` 插件和 `historical-memory` 中已经形成的史学资产。

## 决策

1. 工作台从本机共享技能目录与已安装的 `historical-research` 插件发现 `SKILL.md`，只读取指令和版本指纹，不执行任意脚本。
   - 用户可见技能只保留具有明确输入、产物和人工决定的动作；
   - router、project workflow 和唯一写作主体属于 Harness 内部策略；
   - 原页锚点、状态机、数据契约和校验器属于程序级硬约束，不包装成技能按钮。
2. `historical-humanizer-zh` 作为独立的“史学去模板化”操作；原章节始终保留，模型只生成待审副本。
3. 主页提供技能与插件库。用户可见研究动作支持 `/skill-name 任务`；运行时把技能 SHA-256、插件 Agent 程序 SHA-256 和指令写入 Run 快照。Harness 策略拒绝直接 `/` 调用。
4. 精确保护引文、脚注、页码、数字、来源标识、外文和限定词。事实、归因、因果、范围与限定仍须人工逐段复核。
5. 文风画像允许多位作者、个人或课题组并存。一次生成只能选择一个主画像；不得自动平均混合多人文本，也不得模仿具体学者的可识别措辞。
6. 每个样本必须是至少 800 字符的完整批准稿件，并以稿件版本组合和文本指纹去重。客户端不在画像中保存第二份全文，只保存来源版本、指纹和高层特征。
7. 分级门槛为：1 篇 `OBSERVED_ONCE`；2 篇独立稿件 `RECURRING`；至少 3 篇独立稿件且经作者再次批准，才成为 `STABLE_PROFILE`。不足三篇但用户已批准时为 `AUTHOR_APPROVED`。
8. 新增样本会使旧的批准状态回退到观察或复现阶段，防止未经审核的新聚合画像自动生效。

## 值得适配的既有资产

- 工作流技能：材料验收、问题与范围、文献检索、语料阅读、论证规划、竞争解释、证据冻结、唯一写作、引注、评审与终审。
- 数据契约：`source_manifest.csv`、`search_log.csv`、`reading_manifest.csv`、`evidence_items.csv`、`claim_citation_map.csv`、`revision_protection.json`。
- 校验器：来源清单、检索日志、证据项、主张—引文图和语言修订保护检查。
- 长期记忆：`AUTHOR_APPROVED`/`STABLE_PROFILE` 的用户偏好、高层史学操作、批准与拒绝对照、阴性结果。

以上资产采用版本化适配，不复制成长期漂移的客户端私有副本。插件的代理提示、测试夹具和长期记忆中的原始全文不进入运行时画像。

## 后果

- 更换技能或插件版本时，已有写作提案仍能追溯当时使用的 SHA-256。
- 单篇文章可以帮助提出候选，但不能宣称已经学会稳定文风。
- 长期记忆保持本地、只读接入；跨项目画像写回仍需用户另行批准。
