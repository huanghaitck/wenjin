# ADR 0010｜Windows Desktop Sidecar, Word Bridge and Model Roles

状态：已接受
日期：2026-08-10

## 背景

D4 已经能够在浏览器中完成结构化稿件编辑、人工批准注释和 DOCX 导出，但它仍要求用户手工启动
Python 服务。文章工作台也缺少两个实际使用所需的边界：研究者习惯在 Microsoft Word 中完成精修，
而真实模型目前只能通过启动进程前设置环境变量来配置。

用户授权 D5 完成桌面打包与桥接，并提供《历史研究》页面版式和引文注释规定 DOCX 作为模板核验
依据。

## 决策

### 1. 桌面进程模型

Windows 客户端使用 Tauri 2。Tauri 主进程只负责窗口、本机文件选择、打开外部程序和 Python
sidecar 生命周期；现有 Python harness 继续拥有项目、图书馆、证据、注释和研究对话语义。

Python harness 用 PyInstaller 打包为 sidecar，不要求目标电脑另装 Python。主进程在用户应用数据目录
建立 workspace、library、projects、config 和 logs，选择一个空闲回环端口，启动 sidecar，等待健康检查
通过后再显示主窗口。退出桌面程序时同步结束由它启动的 sidecar。

Tauri 自带的本地页面永久作为顶层安全壳，Python 工作台加载在同窗 iframe 中。研究页面不直接获得
Tauri 内部对象，只能用 `postMessage` 请求白名单命令；壳同时校验消息来源、回环 origin 和命令名。
这避免把本机权限扩散给研究浏览器或以后打开的远程网页。

### 2. 本机桥接边界

桌面页只能调用明确列出的桥接动作：

- 选择一个文献目录并回填图书馆盘点入口；
- 选择 PDF 或 DOCX；
- 打开本地导出文件或其所在目录；
- 把当前 DOCX 交给已安装的 Microsoft Word；
- 显示桌面构建、sidecar、项目 schema 和模板版本。

桥接不暴露任意 shell，不把网页 iframe 变成拥有本机权限的浏览器，也不读取浏览器 Cookie。

### 3. Word 是受控外部编辑器，不嵌入 WebView

不把 Microsoft Word 的窗口或 COM 编辑界面嵌入 Tauri WebView。该方式依赖 Office 安装、位数、
窗口句柄和 COM 生命周期，不能提供可靠的数据与撤销边界。

文章工作台保留结构化文档树作为研究语义的唯一当前版本。用户可以：

1. 以选定期刊模板导出真实 DOCX 脚注；
2. 一键在 Microsoft Word 中打开该精确导出版本；
3. 在 Word 中自行修改并保存；
4. 把修改稿重新导入为新的不可变稿件修订，查看保真报告后再决定采用。

原导出、Word 修改稿和重新导入后的修订不互相覆盖。Word 内的复杂修订、批注、域代码和对象若
不能无损进入当前文档模型，必须出现在保真警告中。

### 4. 模型角色配置

设置页提供三个独立角色：主推理、视觉/OCR、翻译。每个角色可选择 `Ollama` 或
`OpenAI-compatible`，填写模型名、接口地址和超时；远程接口的密钥保存到 Windows Credential
Manager，非秘密配置保存在应用数据目录。项目 SQLite、导出稿和日志不保存 API Key。

界面必须区分“已经保存”“当前可用”“当前被指派”，并显示最近运行实际使用的 provider/model
快照。纯文本主模型可与视觉模型协作，但视觉输出仍只形成待人工核验的 OCR 提案。

### 5. 《历史研究》模板

用户提供的 DOCX 是本轮模板核验依据，不复制或改写原文件。先记录精确文件版本和提取出的规则，
再更新内置模板版本；若源文件被其他程序锁定，模板核验保持待完成，不伪称已经核验。

## 后果

- 浏览器开发模式继续可用，但本机选择、Word 打开和安全密钥保存只在桌面构建中完整可用；
- D5 安装包是可用 Demo，不包含代码签名、自动更新、Office 内嵌、完整 Word 往返或已登录数据库
  自动化；
- 期刊格式会随期刊规则变化，导出时继续显示模板版本和提交前复核状态；
- 桌面壳不复制 Python 业务逻辑，后续仍可独立测试 harness。
- 顶层壳通过 `desktop_url` 拉取 sidecar 地址；研究页面完成 `desktop_status` 握手后才隐藏启动页，
  因而 sidecar 启动竞态不会产生空白或永久停留的成功假象。
