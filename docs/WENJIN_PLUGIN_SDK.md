# 问津领域包工程 0.1.2

领域包不是把另一套程序复制进问津。核心程序负责项目、来源、权限、审批、证据、版本和记忆；领域包通过 MCP 扩展专门研究方法、字段规范、Agent 工具、资料处理器、知识图谱适配器和本地数据接口。

安装后，领域包可以成为具有独立线程和隔离记忆的领域 Agent。它负责专业术语、字段、材料类型、方法规则和自有工具；主 Agent 仍负责项目级调度、跨领域对话和工作台的权限边界。两者可以在同一项目中互相委托，但不共用隐含记忆，也不能绕过 Computer Use、证据和写入审批。

领域 Agent 有独立工作区，用于选择专业 Agent、直接对话、上传材料、查看工具过程和打开候选产物。领域资料仍归档到通用图书馆；处理器、图谱适配器和窄面板只在清单声明且核心已实现对应入口时启用。

## 标准目录

```text
plugin-name/
├─ wenjin-plugin.json
├─ .codex-plugin/plugin.json
├─ .mcp.json
├─ pyproject.toml
├─ skills/plugin-name/SKILL.md
├─ src/plugin_name/mcp_server.py
└─ tests/test_manifest.py
```

`wenjin plugin-create` 可以在研究问题、材料边界、工具动作、权限和数据来源已经明确后生成这一结构。它只是工程骨架，不替代前置编排。安装时问津复制插件目录、记录清单哈希并检查 MCP 命令；原领域项目继续独立维护。

主 Agent 也可以在用户明确要求后调用`domain_pack.create`生成同样的工程骨架。调用前必须先明确研究动作与停止条件、材料与许可证、工具及权限、功能进入问津的位置、运行时和验收方式。该动作会创建文件，因此“请求批准”和“帮我批准”模式都会暂停等待；只有“完全访问”才可在本轮自动执行。Agent只能生成和校验工程，不能替用户决定研究边界、数据许可证或发布方式。

## 权限边界

- `agent_tools` 是主 Agent 可调用的唯一工具白名单。
- 工具应通过 MCP annotations 声明只读、破坏性、幂等和开放世界属性。
- 插件不能直接写问津项目数据库或正式证据表。
- 模型调用、网络访问、复核队列和数据包必须在清单中声明。
- 数据包不放入问津核心安装包；使用 `data_packs` 提供来源、版本、哈希、许可和下载入口。插件维护者取得再分发许可后，可以把数据放入独立插件包，但必须与软件代码许可证分开说明。

## 用户本地数据库

领域包可在 `wenjin-plugin.json` 声明需要用户自行选择的本地数据：

```json
{
  "local_data_sources": [
    {
      "id": "domain-index",
      "label": "领域索引库",
      "label_en": "Domain index",
      "kind": "file",
      "extensions": [".sqlite", ".db"],
      "required": false,
      "description": "选择用户已有的本地SQLite数据库。"
    }
  ]
}
```

用户在“AI 与 Agent—领域包”中选择文件或目录。问津保存绝对路径、大小、修改时间和文件 SHA-256，并通过 `WENJIN_PLUGIN_DATA_BINDINGS` 环境变量把绑定回执交给该领域包的 MCP 进程。问津不复制、不改写用户数据库；领域包必须自行以只读方式打开数据，除非其清单另行声明写权限并经过权限代理批准。

## 多模型岗位

领域 Agent 可在 `wenjin-plugin.json` 中声明多个模型岗位，但仍是一个独立 Agent，不会因此拆成多个研究身份。建议的通用岗位是领域推理、主视觉识读、二次视觉复核和交叉评审／失败兜底。问津界面逐项显示这些岗位，用户可选择跟随主模型、指定其他模型或停用非必需岗位。

配置以 `plugin_name + role_id` 为作用域。多个领域 Agent 可以共用同一API地址、Ollama端口或凭据，也可分别使用不同模型；共用端口不会导致配置覆盖，因为每次启动MCP时只向当前领域进程注入它自己的环境。

问津启动领域 MCP 时会注入 `TEXT_API_*`、`VISION_API_*`、`VISION_QA_API_*` 和 `FALLBACK_API_*`；密钥来自 Windows 凭据管理器，不写入领域包、项目或对话。同一领域 Agent 在 Codex 等其他 MCP 宿主中运行时，宿主可按同名环境变量注入配置；包内只应附带空的示例文件，不得夹带已填密钥。

## 自运行包

发布插件可把 MCP 服务打包为插件目录中的独立可执行文件，并在清单中设置：

```json
{
  "runtime": {
    "type": "mcp_stdio",
    "command": "runtime/plugin-mcp.exe",
    "args": [],
    "cwd": ".",
    "self_contained": true
  }
}
```

问津从安装后的插件副本启动该文件。运行时不得依赖开发者电脑上的 Conda 绝对路径。

## GitHub与外部下载

- Git仓库保存插件源码、构建脚本、Skill、Schema、数据说明和小型测试材料；
- 独立运行时、大型SQLite和完整数据包不提交为普通Git对象；
- 可以把完整ZIP放入GitHub Release，也可以放在机构网站、百度网盘等外部位置；
- GitHub README或Release notes只保存下载链接、版本、SHA-256、文件大小、使用范围和引用方式；
- 问津只负责载入研究者已经下载到本机的ZIP或目录，不保存网盘账号、Cookie和提取码，也不绕过访问控制自动下载。

这种分发方式不影响插件作为标准样例工程：源码工程仍能重建运行时，外部ZIP只是方便普通用户安装。
