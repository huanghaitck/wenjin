# M5 Task Spec｜Skills-Compatible Research Library

状态：已完成
日期：2026-08-10

## 目标

交付桌面打包前可使用的研究图书馆 Demo。用户明确选择一个本地目录后，系统只读盘点 PDF、
Markdown 和 TXT，显示候选及不确定性；只有人工批准的候选才原地登记。图书馆提供书目、标签、
检索、项目关联和完整版本历史，并能发现 `SKILL.md` 指令型技能。

## 核心身份规则

```text
Work（作品）
  └─ Edition（版本、译本、重印或载体说明）
       └─ File（一个持续存在的文件位置记录）
            └─ File Version（一次精确字节状态）
```

- SHA-256 只回答“字节是否完全相同”；
- 同一路径、哈希改变：同一 File 新增 File Version，旧版本保留；
- 不同路径、相同哈希：精确重复候选，保留两个位置，不静默删除；
- 不同路径、书目相似：只提示可能属于同一作品，不自动合并；
- Work/Edition 的合并或拆分由用户决定，不受哈希变化支配。

## 最小流程

1. 用户输入明确目录并选择材料验收 Skill；
2. 系统只读枚举支持的文件，计算元数据、哈希和快速分诊；
3. 展示扫描会话与每个候选的动作、理由、路径、书目建议和版本信息；
4. 用户勾选并批准“原地入库”；
5. 图书馆创建或更新 Work/Edition/File/File Version；
6. 用户可编辑题名、作者、年代、材料类型和标签，并将作品关联到当前项目；
7. 搜索结果可打开完整版本历史和原文件位置。

## 快速分诊

- PDF 使用 PyMuPDF 读取内嵌元数据、总页数、加密/可打开状态和最多前十个物理页的文本；
- Markdown/TXT 只读取有限文本片段；
- 状态包括 `likely_historical`、`uncertain`、`needs_visual_triage`、
  `not_obviously_historical`、`unsupported`、`error`；
- 分诊只帮助整理，不代表项目相关性、引用资格或史料真实性；
- 扫描页无文本时进入 `needs_visual_triage`，M5 不自动调用远程视觉模型。

## Skills 兼容范围

- 从明确配置的根目录发现 `SKILL.md`；
- 读取 name、description、正文说明、相对资源清单和精确文件哈希；
- 扫描会话记录实际选用 Skill 及其哈希；
- 首个样板是 workbench 内置的 `historical-material-intake` adapter；
- M5 不执行 Skill 中的脚本，也不允许 Skill 绕过数据库状态和人工批准。

## 数据与文件安全

- 图书馆使用独立的 `library.sqlite3`，不把全局目录状态塞进单个研究项目；
- 原文件不复制、不移动、不重命名、不改写；
- 版本记录保留哈希、大小与时间，但 M5 不归档旧字节；详情页必须区分“记录存在”和“当前路径仍
  提供该精确字节”，文件再次变化时提示重新盘点；
- 扫描仅限用户本次明确提交的目录；
- 不支持文件和读取错误作为候选保留原因，不伪装为已入库；
- 新入库材料最高为 `FILE_VERIFIED`，不能成为 `CITABLE`。

## 验收标准

- 完整测试套件通过；
- 一个字的文件变化产生同一 File 下的新版本；
- 不同路径相同哈希显示为精确重复候选；
- 扫描前后原文件路径和字节不变；
- 技能名与技能哈希写入扫描会话；
- PDF 最多读取十页并显示分诊理由；
- 题名、作者、标签检索与项目关联可用；
- GUI 可完成扫描、预览、批准、搜索和查看完整版本；
- 使用明确测试目录完成一次真实 PDF 演示。

## 不在 M5

自动移动整理、全盘扫描、任意 Skill 执行、向量库、远程模型分诊、联网检索、登录数据库、
证据卡和证据冻结、长期记忆写入、翻译、正式写作、期刊导出与桌面打包。
