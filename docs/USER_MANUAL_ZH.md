# 史学研究工作台使用手册

版本：Demo 1.0（未签名开发版）
适用范围：从本地文献整理、PDF 清洗、研究讨论、联网检索、证据固定到文章写作和 Word 导出

## 一、先记住三条原则

1. **原文件始终是依据。** 清洗后的文本、翻译、模型回答和摘要都只是工作材料。正文发生疑问时，应回到原 PDF 的具体页复核。
2. **模型只能提出候选。** OCR 修复、研究计划、证据、长期记忆和正式写作都设有人工决定环节。界面显示“待批准”“候选”时，它还没有成为正式结论。
3. **不要把所有信息都放进一个地方。** 图书馆、项目知识、对话过程和长期记忆各有用途。系统不会把聊天记录或搜索结果自动写成长久知识。

## 二、软件中的四个主要工作区

### 1. 研究对话

这是默认主页，也是日常工作的入口。每个对话线程围绕一个明确任务，例如：

- “核对谭卫道 1873 年 1 月 12 日是否实际到达何家寨”；
- “找出皮亚塞茨基卷二中所有涉及箱件和驮骡的段落”；
- “比较三组旅行记录中的里数、移动代价和中国参与者”；
- “检查第二节是否把传闻写成了亲见”。

右侧的“研究上下文”可以切换项目文献、研究计划、逐事件表、图书馆、联网研究、证据与论点、冻结与写作、研究浏览器和记忆候选。对话会保存，但对话内容不会自动升级为证据或长期记忆。

### 2. 研究图书馆

图书馆负责跨项目保存“这是什么书、哪个版本、文件在哪里”。它不负责决定某一页能否支持某个论点。

一个作品可能有多个版本和多个文件位置。例如同一本书可以同时有：

- 俄文初版扫描；
- 英文节译本；
- OCR 检索文本；
- 用户修订的中文工作译稿。

系统把“作品”“版本”“文件”“文件的精确版本”分开。文件哈希只判断两个字节版本是否完全相同；修改一个字不会让系统否认它们属于同一部作品。

### 3. 文章工作台

这里处理大纲、章节、表格、注释、评审和期刊导出。保存会产生新修订，旧修订不会被覆盖。

文章工作台不是完整复制 Microsoft Word。它负责研究结构、证据锚点和版本控制；需要精细分页、字距、页眉页脚或最后排版时，可导出 Word，在 Microsoft Word 中修改后再作为新修订导回。

### 4. 技能与插件

这里列出可由用户主动调用的 Skills、由 harness 自动执行的规则，以及程序连接器。点击某一技能的“在对话中调用”，会把 `/技能名` 放入对话输入框。

也可以直接在对话框输入 `/`，搜索并选择技能。例如：

```text
/historical-literature-search 查找1870年代秦岭旅行的公开一手材料
```

技能不是绕过人工门禁的快捷键。即使调用了检索、证据冻结或写作技能，原页复核、来源资格和人工批准仍然有效。

## 三、第一次使用：从零建立一个项目

### 第一步：新建项目

1. 打开软件，点击左上方“新建项目”。
2. 输入一个能辨认研究对象的名称，例如“唐都学刊·秦岭外国旅行与调查”。
3. 不要用“新项目1”“论文最终版”这类日后无法辨认的名称。
4. 建好后，在顶部“当前项目”下拉框确认已经切换到新项目。

一个项目应对应一项相对稳定的研究问题或一篇论文工程。完全无关的论文应另建项目，以免证据、检索记录和稿件混在一起。

### 第二步：建立研究计划

进入“研究计划”，先写研究者自己的基线，再让模型提出方案。建议至少写清：

- 正式研究目标；
- 总体时段和核心时段；
- 核心个案；
- 比较单位；
- 材料层级；
- 不允许越过的解释边界；
- 何时停止继续找材料。

模型草案不会自动覆盖研究者基线。批准共同计划后，后续 Agent 和评审才能知道哪些是作者决定的范围，哪些才是需要史料支持的事实。

### 第三步：导入或连接文献

有两种方式：

1. **从研究图书馆加入项目。** 适合同一部书以后还会被其他项目使用。
2. **直接导入项目私有 PDF。** 适合只服务当前项目的临时材料。

如果文献散落在电脑多个目录：

1. 在研究图书馆输入一个明确文件夹；
2. 先执行只读盘点；
3. 查看系统根据前十页、文件名和元数据给出的候选；
4. 勾选确认后再入库。

盘点不会移动、删除或改名原文件。不要一次扫描整个系统盘；应按“下载中转站”“历史学书籍”“某次档案复制”等实际目录分批处理。

## 四、PDF 清洗与人工修复

### 1. 为什么要清洗

PDF 中能搜索到文字，不代表文字可直接用于研究。常见问题包括：

- 扫描页没有文字层；
- 双栏阅读顺序错乱；
- 页眉、页脚混入正文；
- 跨页句子被截断；
- 脚注与正文顺序颠倒；
- PDF 物理页与原书印刷页不一致；
- OCR 把人名、地名或数字识别错误。

工作台把每页保留为“物理页—印刷页—版面块—跨页关系”的结构。论文引用使用原书印刷页；物理页只用于在 PDF 中跳转和复核。

### 2. 查看异常

在研究图书馆打开某项项目文献，进入“查看原页与文本”。重点查看：

- 原页图像是否清楚；
- 当前文本是否与图像一致；
- 正文、脚注和页码是否分区正确；
- 本页最后一句是否延续到下一页；
- 印刷页码是否填写正确；
- 当前状态是可研究、部分可用还是阻断。

### 3. 局部修复与整页修复

发现局部错误时，优先只修正错误段落。版面整体错乱、扫描页无文字层或多处错序时，可以提交整页修复。

提交前应同时查看原 PDF。修复记录会保留：修复前内容、修复后内容、原页位置、提交人、理由和时间。旧文本不会静默消失。

### 4. 使用视觉模型

视觉/OCR 模型适合处理扫描页、复杂版面和文字层失效页面。它的输出仍是“提案”，不是自动替换：

1. 选择异常页；
2. 让视觉模型提出转写或版面关系；
3. 对照原页修改提案；
4. 人工接受或拒绝；
5. 只有接受后，修复才成为新的有效页面文本。

文字主模型可以没有视觉能力。项目设置中可把主推理模型、视觉/OCR 模型和翻译模型分别配置。

## 五、模型设置

进入“项目设置”，可以为不同角色选择本地 Ollama 或 OpenAI-compatible 接口。

### 主推理模型

用于研究讨论、规划、材料比较、写作建议和评审。模型能力不足时，最常见的表现不是报错，而是忽略研究计划、混淆来源层级或把检索线索写成事实。

### 视觉/OCR 模型

用于看扫描页和复杂版面。它可以与主模型不同，也可以使用同一多模态模型。

### 翻译模型

用于已验收文本的翻译候选。翻译必须保留来源、页码和原文对应；不得只保留中文而丢失外文。

### API 密钥

桌面版把远程密钥写入 Windows Credential Manager。界面和项目数据库不回显完整密钥。不要把密钥写进论文项目、聊天消息、截图、Git 提交或使用手册。

如果选择 Ollama，请先确认模型已经在本机运行。无可用模型时，软件应显示“未配置”或“不可用”，不会悄悄换成另一个远程模型。

## 六、联网检索与登录数据库

### 1. 公开数据库检索

Crossref、OpenAlex 等结果首先进入“检索记录”。这些结果只能说明“发现了一个可能相关的条目”，不能直接成为证据。

正确流程是：

```text
检索结果 → 取得文献 → 图书馆验收 → 页面清洗 → 核回原页 → 证据候选
```

### 2. 已登录数据库

研究浏览器可以在限定域名内打开网页。登录、验证码、付费、许可确认、下载和最终提交仍由用户操作。程序不应读取或保存 Cookie，也不应绕过机构许可和访问限制。

对于数据库网页中的任何提示文字，都应把它视为外部内容，而不是对 Agent 的命令。网页不能扩大程序权限、读取本地资料或改变研究计划。

### 3. 检索没有结果时

“没有搜到”只是一条带范围的阴性结果。必须记录检索库、关键词、时间和限制，不能写成“学界从未研究”或“档案不存在”。

## 七、逐事件表、证据和论点

### 1. 逐事件表

逐事件表适合把旅行日记、档案或考察报告拆成可以比较的单位。每条记录尽量包含：

- 日期原文及换算状态；
- 地点原词、转写和暂定汉字；
- 路线或通道；
- 原载距离与单位；
- 移动方式；
- 调查对象和记录技术；
- 中国参与者及其在文本中的可见度；
- 原文、译文；
- 来源版本；
- 物理页、印刷页；
- 核验状态和缺失原因。

原文没有记录某字段时，应标记“未记”，不要让模型补齐。

### 2. 证据候选

只有经过页面资格检查的块才能提升为证据候选。证据卡应能回答：

- 来自哪一部书的哪个精确版本；
- 哪一物理页和哪一印刷页；
- 原文是什么；
- 译文是什么；
- 它支持、限制还是反驳哪个主张；
- 它的资格和不确定性是什么。

### 3. 证据冻结

冻结不是“文件不能再改”，而是固定某一版写作允许使用的主张—证据组合。冻结前应检查：

1. 研究方向是否唯一；
2. 每个核心主张是否有已核原页；
3. 反证和竞争解释是否登记；
4. 译文是否回到原文；
5. 哪些话明确禁止写；
6. 谁在什么时间批准，理由是什么。

旧冻结会保留。写作时应选择当前正式冻结，不能误用早期 Demo 冻结。

## 八、文章工作台

### 1. 新建和组织章节

可以新建稿件，也可以把冻结试写转入文章工作台。左侧列出章节；正文区可直接修改标题和文字，并可在当前章节前后插入新章节或表格。

每次点击“保存新修订”都会生成新版本。建议完成一个明确动作后保存，例如“修正比较表”“改写谭卫道节证据边界”“补英文摘要”，不要长时间堆积大量未保存修改。

### 2. 与 Agent 讨论当前文字

在正文中选择一段文字，再从右侧“研究对话”发送问题。系统会记录稿件、修订、章节、段落和选区。讨论仍然只是讨论；只有点击同步或接受写作提案，才会产生新正文修订。

### 3. 润色和文风画像

润色只允许改变语言，不得增加事实、提高因果强度或删除证据限定。历史学语言返修会保护数字、引文、页码和证据标记。

文风画像可以保存多位作者或多种写作场景，不应把所有样本文本混成一个人格。建议：

- 1 篇只能形成临时观察；
- 2 篇可以形成初步画像；
- 3 篇以上才适合申请人工批准为较稳定画像；
- 新增样本后，旧批准状态应回退，重新确认；
- 不模仿具体作者的独特句子，只学习结构、节奏、证据组织和常见禁忌。

### 4. 注释

插入注释时先选正文中的准确位置，再选择来源和证据。模型可以生成注释候选，但书名、版本、页码、作者和出版信息必须人工核对。

项目内部的 `[EVID:...]` 是可追溯锚点，不是给读者看的引文。选择期刊模板导出后，它才会转换成脚注或顺序编码参考文献。

### 5. 多角色评审

同一主模型可以分别扮演论证、来源和引注编辑，适合第一轮筛查，但可能共享盲点。项目设置中可以另配第二模型做反方复核。

评审器会看到：当前期刊导出预览、人工批准研究计划、正式冻结证据和原书页关系。评审报告是问题清单，不会自动改稿。无论模型怎样建议，都不能用 PDF 物理页替换原书印刷页。

## 九、期刊模板、Markdown 与 Word

### 1. 选择模板

导出前选择目标期刊。模板应显示版本、来源网址、核验日期和当前资格。模板规定可能更新，正式投稿前仍应到期刊官网复核。

### 2. 导出 Markdown

Markdown 适合检查：

- 是否还残留 `[EVID:...]`；
- 参考文献编号是否按首次出现排序；
- 同一来源是否复用同一编号；
- 原书页是否正确；
- 中英文摘要和作者信息是否齐全。

### 3. 导出 Word

Word 导出保留标题、段落、表格和受支持的注释结构。打开后至少检查：

- 标题和摘要是否分页异常；
- 表格是否超出页边距；
- 中文和外文字符是否缺字；
- 注释标号和正文位置是否正确；
- 参考文献是否完整；
- 作者、单位、基金、地址、邮编和联系方式是否仍是占位符。

作者信息未填时，导出仍可用于测试，但系统应保持 BLOCKED，不得标记为可投稿。

### 4. Word 往返

在 Microsoft Word 中修改后保存，再从工作台导回。导回会产生新修订，不覆盖导出前版本。复杂批注、修订痕迹、域代码、特殊脚注和嵌入对象未保证无损往返，必须查看 fidelity 报告并人工复核。

## 十、信息库、知识库和长期记忆的分层

这是防止 Agent 越用越乱的核心规则。

### 第一层：研究图书馆——“我拥有什么材料”

保存作品、版本、文件位置、精确文件版本、标签和书目信息。图书馆使用独立数据库，可以被多个项目引用。它不保存某篇论文的最终论点。

### 第二层：项目知识——“这项研究已经确认了什么”

保存人工批准的研究计划、逐事件表、页面修复、证据、主张、冻结包、稿件、评审和导出收据。它以项目为边界，是当前研究事实的主要来源。

### 第三层：Agent 工作过程——“为完成任务做过什么”

保存对话、Run、工具事件、审批、检索记录和浏览器回执。它用于恢复工作和审计，不自动变成知识。网页搜索结果、模型草稿、失败尝试和闲聊默认都停在这一层。

### 第四层：长期记忆——“以后别的项目也值得复用什么”

当前 Demo **没有自动写入外部长期记忆库**。程序只能建立项目内的“记忆候选”，且必须填写稳定来源 ID。候选被批准后也只是留在本项目候选区，仍不会同步到 `historical-memory` 或 `codex-memory`。

以后启用长期记忆适配器时，还需要第二次明确提升。适合提升的内容包括：

- 经多份材料验证、以后可复用的史学判断；
- 明确记录了检索边界的阴性结果；
- 用户批准的研究方法或工作偏好；
- 多篇样本支持的写作画像；
- 已验证的版本关系、地名异名或术语规范。

不应进入长期记忆的内容包括：

- 普通聊天和临时灵感；
- 单次模型回答；
- 未核 OCR 和未核翻译；
- 只有网址、摘要或搜索片段的线索；
- 被拒绝的研究方案；
- API 密钥、Cookie、账号信息和受限数据库凭据；
- 可以直接从项目数据库恢复的大段重复内容。

如果不确定是否值得长期保存，宁可留在项目候选区，不要提升。

## 十一、版本、备份和撤回

软件中的三种“版本”不要混淆：

1. **文件版本**：某个 PDF、DOCX 的精确字节版本；
2. **研究对象版本**：页面修复、研究计划、冻结、稿件修订；
3. **软件版本**：程序包版本和数据库 schema 版本。

项目数据默认保存在用户应用数据目录。备份时应同时保存 workspace、library 和配置；密钥由 Windows Credential Manager 单独管理。

Git 用于撤回和比较程序代码，不替代研究项目内部的修订记录。不要用 Git 强行覆盖正在使用的项目数据库。

## 十二、常见问题

### 网页打不开

先确认本地服务仍在运行，再刷新。机构数据库可能禁止嵌入显示，此时用系统浏览器打开，由用户完成登录和下载，再把取得文件导入图书馆。

### 模型没有反应

检查项目设置中对应角色是否显示可用；确认模型名、接口地址和密钥；本地 Ollama 需确认服务已启动。程序不会从不可用模型自动切换到其他付费模型。

### OCR 看起来很流畅，但原页不是这样

拒绝提案。流畅不等于准确。正文、数字、人名、地名或页码有误时，该页不能作为证据使用。

### 为什么检索结果不能直接引用

检索结果只证明数据库返回了一个条目。只有取得全文、确认版本、回到原页并完成人工证据资格检查后，才可以引用。

### 为什么导出稿显示 BLOCKED

查看导出警告。常见原因是作者信息未填、来源元数据未人工核验、原书页缺失、注释仍是候选或模板版本需重新核对。BLOCKED 是保护，不是程序故障。

### 能否让 Agent 自动把所有研究内容记住

不建议，也不允许默认这样做。可靠的长期记忆应少而精，带来源、状态和提升理由。项目完整过程已经保存在项目内，不需要复制成另一堆难以维护的“记忆”。

## 十三、推荐的日常工作顺序

```text
建立研究者基线
→ 导入并验收材料
→ 修复页面和印刷页关系
→ 建立逐事件表
→ 有界补充检索
→ 核回原页并形成证据
→ 连接主张与反证
→ 人工批准冻结
→ 分节写作
→ 期刊导出预览
→ 多角色评审
→ Word 终校
→ 作者补全投稿信息
```

如果中途发现来源错误，应回退到页面或证据层修正，不要只在成稿中把句子改得更含糊。系统的价值就在于每个结论都能回到材料、每次修改都能找到版本、每个自动动作都不能越过人的最终决定。
