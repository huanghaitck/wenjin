# 问津｜人文社会科学研究工作台使用手册

[English](USER_MANUAL_EN.md) | 中文

版本：0.1.1 Public Preview（安装程序尚未签名）
核对日期：2026-08-21
适用范围：从本地文献整理、PDF 清洗、研究讨论、联网检索、证据固定到文章写作和 Word 导出

> **当前版本边界**
>
> 这是本地优先的研究工作台，不是无人值守的“自动写论文”程序，也不是完整的 Word、Zotero、知网或 Obsidian 替代品。界面中没有按钮的功能，不应假定可以自动完成。当前没有从“版本”页直接回退正文，也没有受限数据库的无人值守批量下载。桌面版会为发生变化的完整项目建立SQLite备份；外部长期记忆仍只接收人工批准的候选。

## 一、先记住三条原则

1. **原文件始终是依据。** 清洗后的文本、翻译、模型回答和摘要都只是工作材料。正文发生疑问时，应回到原 PDF 的具体页复核。
2. **模型只能提出候选。** OCR 修复、研究计划、证据、长期记忆和正式写作都设有人工决定环节。界面显示“待批准”“候选”时，它还没有成为正式结论。
3. **不要把所有信息都放进一个地方。** 图书馆、项目知识、对话过程和长期记忆各有用途。系统不会把聊天记录或搜索结果自动写成长久知识。

## 二、软件中的五个主要入口

### 1. 研究对话

这是默认主页，也是日常工作的入口。每个对话线程围绕一个明确任务，例如：

- “核对谭卫道 1873 年 1 月 12 日是否实际到达何家寨”；
- “找出皮亚塞茨基卷二中所有涉及箱件和驮骡的段落”；
- “比较三组旅行记录中的里数、移动代价和中国参与者”；
- “检查第二节是否把传闻写成了亲见”。

右侧的“研究上下文”可以切换项目文献、研究计划、逐事件表、图书馆、联网研究、证据与论点、冻结与写作、研究浏览器和记忆候选。对话会保存，但对话内容不会自动升级为证据或长期记忆。

对话顶部还有两种工作状态：

- **独立构思（隐藏研究者意图基线）**：不把旧线程对话、研究者基线或共同计划发送给模型，适合先看模型能否独立提出方案；
- **按共同计划执行**：加载已经人工批准的共同计划和最近的有界线程历史，适合继续同一任务。旧对话仍不是来源证据，涉及事实时必须重新打开原页。

第一次使用时要先点击研究线程旁的“＋”新建线程。没有可用的主模型时，“发送”按钮会停用，应先到“AI 与 Agent”保存并测试模型。

### 2. 研究图书馆

图书馆负责跨项目保存“这是什么书、哪个版本、文件在哪里”。它不负责决定某一页能否支持某个论点。

一个作品可能有多个版本和多个文件位置。例如同一本书可以同时有：

- 俄文初版扫描；
- 英文节译本；
- OCR 检索文本；
- 用户修订的中文工作译稿。

系统把“作品”“版本”“文件”“文件的精确版本”分开。文件指纹只用来判断两个文件是否完全相同；修改一个字会形成新的文件版本，但不一定是另一部作品。

当前图书馆还有六个可人工调整的书架：“原始史料”“学术论文”“学术专著”“个人论文与稿件”“工具书与目录”“待分类”。移动书架只改变整理位置，不改变材料能否引用，也不移动电脑上的原文件。

“知识图谱”把已登记的作品、作者、年代、出版社、书架和人工标签显示为关系网。它首先是书目发现工具；0.1 不会把模型猜测的人物关系、因果或事件自动写入图谱。

“史料长编”只收录已经人工批准、能够回到精确来源版本与页码的逐事件记录。它可以按关键词、年份和个案筛选，点击记录可返回原页，并可导出 Markdown。长编不是“已经穷尽全部史料”的声明。

### 3. 文章工作台

这里处理大纲、章节、表格、注释、评审和期刊导出。保存会产生新修订，旧修订不会被覆盖。

文章工作台不是完整复制 Microsoft Word。它负责研究结构、证据锚点和版本控制；需要精细分页、字距、页眉页脚或最后排版时，可导出 Word，在 Microsoft Word 中修改后再作为新修订导回。

### 4. 技能与插件

这里列出可由用户主动调用的 Skills、由 harness 自动执行的规则，以及程序连接器。点击某一技能的“在对话中调用”，会把 `/技能名` 放入对话输入框。

也可以直接在对话框输入 `/`，搜索并选择技能。例如：

```text
/historical-literature-search 查找某一时段区域旅行史的公开一手材料
```

技能不是绕过人工门禁的快捷键。即使调用了检索、证据冻结或写作技能，原页复核、来源资格和人工批准仍然有效。

当前Skills以可追溯的指令方式工作：按钮把斜杠命令放入对话框，并记录本次实际使用的Skill版本；它不会在后台任意执行Skill文件夹中的脚本。由程序负责的内部流程没有直接调用按钮，应从相应研究阶段或功能页面进入。

同一项目还能通过 `wenjin mcp-server 项目目录` 作为本地 MCP 服务提供给其他 Agent；通过 `wenjin --help` 使用命令行。MCP 0.1 提供项目状态、图书馆检索、来源详情和稿件结构等只读工具，不会绕过写入审批。

0.1.1还支持领域包。领域包安装后会复制到问津配置目录并登记具体版本。它可以通过Skill、工具、资料处理器、字段规范、知识图谱和本地数据接口扩展研究能力，主Agent只能调用领域包明确提供的工具。问津公开版不预装具体学科样例或用户数据。

领域包可以从目录或 `.zip` 安装。自运行领域包应把 MCP 可执行文件和所需的非受限配置放在包内，不依赖开发者电脑上的 Conda 路径。需要创建新领域包时，可使用 `wenjin plugin-create`，也可在界面或明确授权主 Agent 生成标准的问津清单、Codex清单、MCP入口、Skill和测试骨架。

### 5. AI 与 Agent

这里显示软件与项目 schema 版本、桌面桥接状态、研究人格、主模型、辅助模型、MoA、记忆分层、可用 Skills、MCP、连接器和隐私边界。它用于确认“当前实际能做什么”；只有明确设为“自动”的辅助任务才会复用主模型，其他未配置角色不会被悄悄替换。

“连接器与 MCP”中的 Codex 双向桥接有两个方向：点击注册后，Codex 可以通过只读 MCP 查看问津项目；从问津启动 Codex 任务时，程序只传递当前项目目录、明确提示和所选沙箱，沿用本机 Codex 登录，不读取凭据。每项任务保存 JSONL 事件、错误日志和最终答复。

同页的“微信连接”使用普通微信扫码，把获准联系人的私聊文字交给当前问津项目。登录信息保存在Windows安全凭据中。0.1.1只回复收到的私聊文字；群聊、主动推送和文件尚未开放。若Agent动作需要批准，微信会提示回到问津客户端处理。

“当前状态”中的项目备份采用SQLite在线备份和完整性检查。恢复不会覆盖当前项目，而是新建一个项目副本。启动时只有数据库发生变化才新增备份。

“记忆”页面可分别配置史学长期记忆和工程长期记忆目录。只有状态为 `approved_local` 的候选才能提升；每次提升只在目标库 `90_INBOX` 生成一张 `draft` Markdown卡，保留项目及来源回链，不复制聊天全文、OCR草稿或来源文件。

## 三、第一次使用：从零建立一个项目

### 第一步：新建项目

1. 打开软件，点击左上方“新建项目”。
2. 输入一个能辨认研究对象的名称，例如“某期刊·晚清区域旅行史研究”。
3. 不要用“新项目1”“论文最终版”这类日后无法辨认的名称。
4. 建好后，在顶部“当前项目”下拉框确认已经切换到新项目。

一个项目应对应一项相对稳定的研究问题或一篇论文工程。完全无关的论文应另建项目，以免证据、检索记录和稿件混在一起。

### 第二步：建立研究计划

进入“研究计划”，先写研究者自己的基线，再让模型提出方案。建议至少写清：

- 正式研究目标；
- 总体时段和核心时段；
- 核心个案；
- 比较单位；
- 材料层级；
- 不允许越过的解释边界；
- 何时停止继续找材料。

模型草案不会自动覆盖研究者基线。批准共同计划后，后续 Agent 和评审才能知道哪些是作者决定的范围，哪些才是需要史料支持的事实。

### 第三步：导入或连接文献

有两种方式：

1. **从研究图书馆加入项目。** 适合同一部书以后还会被其他项目使用。
2. **直接导入项目私有 PDF。** 适合只服务当前项目的临时材料。

如果文献散落在电脑多个目录：

1. 在研究图书馆输入一个明确文件夹；
2. 先执行只读盘点；
3. 查看系统根据前十页、文件名和元数据给出的候选；
4. 勾选确认后再入库。

后台只读盘点进行时，可以离开图书馆页；刷新后会恢复最近一次盘点进度。候选每页最多显示 50 条。PDF 只读取前十页作分诊，DOCX、Markdown 和 TXT 只读取有限的前段文本；这只是整理建议，不是学术判断。DOC、EPUB、CAJ 和常见图片会出现在盘点收据中，但当前版本不直接解析、也不能批准入库。CAJ 应保留原件，另行生成带转换回执的 PDF 或逐页文本。

盘点不会移动、删除或改名原文件。不要一次扫描整个系统盘；应按“下载中转站”“历史学书籍”“某次档案复制”等实际目录分批处理。大目录第一次盘点可能较慢，应看“已检查”数量而不是反复点击。盘点失败时，已经发现的候选仍会留在本次收据中。

入库后还要完成两步，材料才会进入研究：

1. 在“作品与版本”中核对题名、责任者、版本、出版信息、标签和书架；
2. 点击“加入当前项目文献”，把当前精确 PDF 版本复制进项目并进行逐页处理。DOCX 可作为定位文本加入项目，但不能直接充当原页证据；图书馆中的 Markdown/TXT 当前不能通过项目桥接成为项目文献。

如果图书馆显示“文件自上次登记后又有变化”，须重新盘点；如果显示“原文件当前位置已不可用”，系统只保留登记记录，不能据此打开旧字节。工作台没有替你归档所有历史文件版本。

## 四、PDF 清洗与人工修复

### 1. 为什么要清洗

PDF 中能搜索到文字，不代表文字可直接用于研究。常见问题包括：

- 扫描页没有文字层；
- 双栏阅读顺序错乱；
- 页眉、页脚混入正文；
- 跨页句子被截断；
- 脚注与正文顺序颠倒；
- PDF 物理页与原书印刷页不一致；
- OCR 把人名、地名或数字识别错误。

工作台把每页保留为“物理页—印刷页—版面块—跨页关系”的结构。论文引用使用原书印刷页；物理页只用于在 PDF 中跳转和复核。

0.1.1 可以从原页界面导出两种阅读本：

- “当前阅读 Markdown”使用当前有效文本，可能包含尚未逐段人工核验的内容；
- “仅核验 Markdown”只使用人工核验或修复且可研究的块。

两种阅读本都保留来源版本、物理页、印刷页和块标识。它们不会覆盖逐页核验 Markdown；只有人工确认的跨页关系才会在阅读本中标为续接。

### 2. 查看异常

有两条等价入口：在“研究图书馆”的“当前项目文献”选择来源后点击“打开原页与文本复核”，或在主页右侧“项目文献”点击“查看原页与文本”。重点查看：

- 原页图像是否清楚；
- 当前文本是否与图像一致；
- 正文、脚注和页码是否分区正确；
- 本页最后一句是否延续到下一页；
- 印刷页码是否填写正确；
- 当前状态是可研究、部分可用还是阻断。

### 3. 局部修复与整页修复

发现局部错误时，优先只修正错误段落。版面整体错乱、扫描页无文字层或多处错序时，可以提交整页修复。

提交前应同时查看原 PDF。修复记录会保留：修复前内容、修复后内容、原页位置、提交人、理由和时间。旧文本不会静默消失。

当前页面复核界面的常用顺序是：

1. 填写“复核人”和“修正依据”；
2. 按原书页眉或页脚填写“印刷页码”，保存物理页与印刷页的对应；
3. 展开“正文与标题”“脚注”或“页眉、页脚与页码”，逐段核对；
4. 小错用“保存这段修正”，无误段用“确认此段与原图一致”；
5. 双栏错序可先点“按双栏阅读顺序重排”，但仍须逐段检查，再提交整页修正；
6. 在“跨页关系”中确认句子是否续接以及正确端点；
7. 没有阻断性异常后，才点“确认本页与原图一致”。

“标记整份文件不符”用于文件身份确实错误或系统性不可用的情况，不应拿来处理一两个 OCR 错字。执行后整份来源会被阻断，但原文件和审计记录保留。

同一来源还应展开“核验这份文献的引文元数据”，按题名页、版权页或期刊首页填写作者、题名、版本、出版地、出版者、年份、刊名、卷期和页码范围，并保存核验人。页面文字已核不等于书目信息已核；后者缺失时，Word/Markdown 导出会继续给出阻断警告。

### 4. 使用视觉模型

视觉/OCR 模型适合处理扫描页、复杂版面和文字层失效页面。它的输出仍是“提案”，不是自动替换：

1. 选择异常页；
2. 让视觉模型提出转写或版面关系；
3. 对照原页修改提案；
4. 人工接受或拒绝；
5. 只有接受后，修复才成为新的有效页面文本。

文字主模型可以没有视觉能力。“AI 与 Agent”中可把主模型和视觉/OCR、翻译等辅助任务分别配置，也可让辅助任务自动复用主模型。

## 五、模型设置

进入“AI 与 Agent”，先配置主模型，再按需要配置视觉/OCR、翻译、联网材料整理、上下文压缩、标题与摘要命名、交叉评审六类辅助任务。辅助任务可选“自动（跟随主模型）”“未启用”“本地 Ollama”或“OpenAI 兼容接口”。DeepSeek、OpenRouter、SiliconFlow、智谱 GLM 等预设会填写常用接口地址；点击“刷新模型列表”可以从接口读取当前模型，保存前仍应使用“测试连接”核对。

“研究人格（Soul）”用于规定助手如何称呼研究者、学科取向、主动性边界和写作习惯。每次保存都会产生一个可追溯版本。人格可以改变协作方式，不能取消原页、证据、审批、版本和隐私规则。

MoA 允许若干辅助模型先独立提出意见，再由主模型综合并执行。参考模型不能调用工具，单个参考模型失败也不会让整次研究运行失败。没有明确比较收益时不要为了“模型更多”而打开它。

### 主推理模型

用于研究讨论、规划、材料比较、写作建议和评审。模型能力不足时，最常见的表现不是报错，而是忽略研究计划、混淆来源层级或把检索线索写成事实。

### 视觉/OCR 模型

用于看扫描页和复杂版面。它可以与主模型不同，也可以使用同一多模态模型。

### 翻译模型

用于已验收文本的翻译候选。翻译必须保留来源、页码和原文对应；不得只保留中文而丢失外文。

### 交叉评审模型

这是可选角色。先用主模型完成论证、史料和引注三角色评审后，才可让第二模型做反方复核。未配置第二模型并不妨碍基本写作，但不能声称已经完成异构模型复核。

### API 密钥

桌面版把远程密钥写入 Windows Credential Manager。界面和项目数据库不回显完整密钥。不要把密钥写进论文项目、聊天消息、截图、Git 提交或使用手册。

如果选择Ollama，请先确认Ollama服务和所填模型已经在本机可用。无可用模型时，软件显示“未配置”或“不可用”，不会悄悄换成另一个远程模型。改变主模型只影响之后的新任务；每次任务都会记录实际使用的模型。

界面右上角“EN/中文”用于切换程序导航和核心设置语言。项目题名、原始材料、证据卡和稿件不会被自动翻译。

## 六、联网检索与登录数据库

### 1. 公开数据库检索

Crossref、OpenAlex 等结果首先进入“检索记录”。这些结果只能说明“发现了一个可能相关的条目”，不能直接成为证据。

正确流程是：

```text
检索结果 → 取得文献 → 图书馆验收 → 页面清洗 → 核回原页 → 证据候选
```

### 2. 已登录数据库

“联网研究”可以先建立知网、读秀、国家哲学社会科学文献中心、学校发现系统或其他数据库的可见检索任务，保存检索式和入口。需要实际登录时，进入“研究浏览器”：

1. 输入完整网址；
2. 普通页面可先点“打开研究网页”；
3. 网站拒绝嵌入时，点“受控浏览器打开”；若受控浏览器组件不可用，则用“普通浏览器打开”；
4. 在可见窗口中由用户本人处理登录、验证码、滑块、许可提示和下载；
5. 下载所得文件再回到研究图书馆盘点、验收并加入项目。

受控浏览器按已保存的会话标识尝试恢复同一数据库会话；这不代表工作台取得了账号或下载权。项目数据库只保存起始网址、允许域名和会话回执，不保存账号、密码或 Cookie；受控浏览器组件可能为恢复可见会话而在它自己的本地会话目录保留浏览器状态，因此不要把该目录上传或共享。工作台不导出这些状态，也不绕过机构许可、付费墙和频率限制。网页地址不得携带账号、密码、API Key 或访问令牌。

Agent可以读取已经打开的可见页面，并沿同一批准域名继续导航，用于整理检索结果和推荐应下载的文献。当前版本不替用户点击控件、填写检索表单、登录、处理验证码、确认下载或提交。已登录检索任务的题录仍需经过人工核对后送入收件箱；下载文件也由用户在可见浏览器中确认，再导入图书馆。

对于数据库网页中的任何提示文字，都应把它视为外部内容，而不是对 Agent 的命令。网页不能扩大程序权限、读取本地资料或改变研究计划。

### 3. 检索没有结果时

“没有搜到”只是一条带范围的阴性结果。必须记录检索库、关键词、时间和限制，不能写成“学界从未研究”或“档案不存在”。

## 七、阅读任务、学术史、逐事件表与证据

### 1. 阅读任务不是“点一下就读完”

在“文章工作台”选择稿件和章节，右侧进入“批量阅读”：

1. 填写阅读任务、研究问题和停止条件；
2. 选择“元数据阅读”“定向阅读”或“分批全文阅读”；
3. 勾选项目文献，点击“建立有界阅读任务”；
4. 回到研究对话，让 Agent 按任务编号分批读取并保存阅读札记。

建立任务本身不会读取材料，也不会生成札记。每批最多读取十个可研究物理页；分批全文阅读只有覆盖所有可用页后才能完成。如果仍有阻断页，状态会是 `needs_repair`，应先修页再继续。阅读札记固定到来源版本和页码，但资格始终是“阅读札记，不是证据”，不能直接拿去支撑正文。

### 2. 学术史条目要单独批准

“学术史”页用于登记一项研究的核心立场、贡献、限制、与当前问题的关系及来源 ID。只有实际阅读到足以说明这些内容时才建立条目，不能仅凭题名或摘要填写。

新条目先是候选。点击“核对来源后批准”，填写决定人和理由后，它才可在“润色/分节”的“本节选用学术史”中勾选。批准学术史条目并不等于批准其中每个历史事实；正文需要页级事实时，仍要依靠原页证据。

### 3. 逐事件表

逐事件表适合把旅行日记、档案或考察报告拆成可以比较的单位。每条记录尽量包含：

- 日期原文及换算状态；
- 地点原词、转写和暂定汉字；
- 路线或通道；
- 原载距离与单位；
- 移动方式；
- 调查对象和记录技术；
- 中国参与者及其在文本中的可见度；
- 原文、译文；
- 来源版本；
- 物理页、印刷页；
- 核验状态和缺失原因。

原文没有记录某字段时，应标记“未记”，不要让模型补齐。

Agent 生成的是候选事件。每条候选必须打开原页核对，必要时按当前已核锚块刷新原文，再填写决定人与理由批准或拒绝。已批准事件仍不是写作冻结证据；还须在“冻结与写作”把事件和可写主张组成冻结包。

### 4. 证据候选

只有经过页面资格检查的块才能提升为证据候选。证据卡应能回答：

- 来自哪一部书的哪个精确版本；
- 哪一物理页和哪一印刷页；
- 原文是什么；
- 译文是什么；
- 它支持、限制还是反驳哪个主张；
- 它的资格和不确定性是什么。

最小操作路径是：在“证据与论点”建立候选主张，先打开目标项目文献并逐段核验，再选择连续的“证据起始段—结束段”，检查原文、关系和说明，最后点“人工提交证据”。机器解析段、阻断段、页眉页脚和未核页面不会进入可选清单。证据关系包括支持、削弱、背景和反证，不能把后二者改写成支持。

### 5. 证据冻结

冻结不是“文件不能再改”，而是固定某一版写作允许使用的主张—证据组合。冻结前应检查：

1. 研究方向是否唯一；
2. 每个核心主张是否有已核原页；
3. 反证和竞争解释是否登记；
4. 译文是否回到原文；
5. 哪些话明确禁止写；
6. 谁在什么时间批准，理由是什么。

旧冻结会保留。写作时应选择当前正式冻结，不能误用早期 Demo 冻结。

当前有两条冻结入口：

- 普通主张—证据冻结：勾选已有页块证据的主张，创建待批准包；
- “逐事件表正式冻结”：只能选择已经人工批准且保留原页锚点的事件，并应填写最低可写主张、不能支持的强说法、未决项和禁止主张。

两类材料目前不能在前台混成同一个新冻结包。待批准包仍不能驱动正式分节写作；必须填写决定人和批准依据，点击“人工批准冻结”。文章工作台一次只选择一个批准冻结包，再从包内多选本节允许使用的证据。

## 八、文章工作台

### 1. 新建和组织章节

可以新建稿件，也可以把冻结试写转入文章工作台。左侧列出章节；正文区可直接修改标题和文字，并可在当前章节前后插入新章节或表格。

每次点击“保存新修订”都会生成新版本。建议完成一个明确动作后保存，例如“修正比较表”“改写谭卫道节证据边界”“补英文摘要”，不要长时间堆积大量未保存修改。

### 2. 与 Agent 讨论当前文字

在正文中选择一段文字，再从右侧“研究对话”发送问题。系统会记录稿件、修订、章节、段落和选区。讨论仍然只是讨论；只有点击同步或接受写作提案，才会产生新正文修订。

### 3. 分节写作、选区与整表返修

在“润色/分节”可以选择四种操作：保真润色、依据已批准正文生成摘要/投稿信息、史学去模板化、基于冻结证据分节写作。

基于冻结证据写一节时，应选择一个已批准冻结包，再多选本节允许使用的证据；候选冻结和未选证据不会进入上下文。学术史也要逐节勾选。生成结果先进入“对照待审写作提案”，只有证据合同检查通过，并由用户填写决定人和理由后批准，才会成为新章节版本。

“仅返修当前选区”目前只用于“保真润色”，不是任意重写：

- 文字选区须在当前章节的同一或连续段落内，而且选中文字在本节中必须能唯一定位；
- 表格必须完整选择一张表，不能只选部分单元格，也不能把表格和段落混选；
- 完整单表可以额外选择一个批准冻结包及其证据，用于有证据约束的整表补充；普通文字选区不能借此新增证据；
- 整表补证不能同时新增学术史上下文；如需补学术史，应另做一轮有明确边界的章节处理；
- 表格提案若不再是完整有效的 Markdown 表格，或删改既有数字、来源标记、引文和限定，会被阻断；
- 返修结果会回填为完整章节的新版本，未选部分应保持不变。

如果界面提示“正文尚未同步当前批准章节”，先人工确认并点击“同步到正文并创建新修订”，否则导出仍会使用中央正文而不是侧栏中的新章节版本。

### 4. 润色和文风画像

润色只允许改变语言，不得增加事实、提高因果强度或删除证据限定。历史学语言返修会保护数字、引文、页码和证据标记。

文风画像可以保存多个作者或写作场景，但一个画像内必须保持同一作者、同类已核全文，不应把不同人的文字混成一个人格。当前界面只保存高层特征和版本指纹，不另存一份全文，也不会自动抓取或模仿具体句子：

- 1 篇是 `OBSERVED_ONCE` 候选观察；
- 最少 3 篇同一作者的独立、已核全文论文，且经人工批准，才成为可选择的 `STABLE_PROFILE`；建议补足 5 篇；
- 新增样本后，旧批准状态应回退，重新确认；
- 不模仿具体作者的独特句子，只学习结构、节奏、证据组织和常见禁忌。

研究来源和文风样本必须分开。外部文风论文只有在书目和全文都已核验时才可加入；一部专著或单篇论文不能被宣称为“已经学会该作者文风”。文风画像目前只用于“史学去模板化（证据保真）”，不会自动套用到所有写作操作。

### 5. 注释

插入注释时先选正文中的准确位置，再选择来源和证据。模型可以生成注释候选，但书名、版本、页码、作者和出版信息必须人工核对。

项目内部的 `[EVID:...]` 是可追溯锚点，不是给读者看的引文。选择期刊模板导出后，它才会转换成脚注或顺序编码参考文献。

### 6. 多角色评审

同一主模型可以分别扮演论证、来源和引注编辑，适合第一轮筛查，但可能共享盲点。项目设置中可以另配第二模型做反方复核。

评审器会看到：当前期刊导出预览、人工批准研究计划、正式冻结证据和原书页关系。评审报告是问题清单，不会自动改稿。无论模型怎样建议，都不能用 PDF 物理页替换原书印刷页。

## 九、投稿模板、Markdown 与 Word

### 1. 选择模板

界面在编辑器工具栏称“投稿模板”，右侧页签称“期刊模板”，两者使用同一套带版本规则。导出前选择目标期刊。模板应显示版本、来源网址、核验日期和当前资格。模板规定可能更新，正式投稿前仍应到期刊官网复核。

### 2. 导出 Markdown

Markdown 适合检查：

- 是否还残留 `[EVID:...]`；
- 参考文献编号是否按首次出现排序；
- 同一来源是否复用同一编号；
- 原书页是否正确；
- 中英文摘要和作者信息是否齐全。

### 3. 导出 Word

Word 导出保留标题、段落、表格和受支持的注释结构。打开后至少检查：

- 标题和摘要是否分页异常；
- 表格是否超出页边距；
- 中文和外文字符是否缺字；
- 注释标号和正文位置是否正确；
- 参考文献是否完整；
- 作者、单位、基金、地址、邮编和联系方式是否仍是占位符。

作者信息未填时，导出仍可用于测试，但系统应保持 BLOCKED，不得标记为可投稿。

### 4. Word 往返

在 Microsoft Word 中修改后保存，再从工作台导回。导回会产生新修订，不覆盖导出前版本。“在 Microsoft Word 中打开”“导回 Word 修改稿”和系统文件选择器只在安装后的 Windows 桌面客户端可用；普通浏览器模式仍可下载导出的 DOCX，但没有原生 Word 桥接。

Word 往返是有限保真：批注、修订痕迹、域代码、原有脚注和嵌入对象不保证无损，复杂合并单元格也要人工复核。导出的工作台批准脚注是真实 Word 脚注，但圈码外观、每页重新编号和最终分页仍须在目标 Word 版本中检查。务必查看“版本”页的导入/导出保真回执。

## 十、信息库、知识库和长期记忆的分层

这是防止 Agent 越用越乱的核心规则。

### 第一层：研究图书馆——“我拥有什么材料”

保存作品、版本、文件位置、精确文件版本、标签和书目信息。图书馆使用独立数据库，可以被多个项目引用。它不保存某篇论文的最终论点。

### 第二层：项目知识——“这项研究已经确认了什么”

保存人工批准的研究计划、逐事件表、页面修复、证据、主张、冻结包、稿件、评审和导出收据。它以项目为边界，是当前研究事实的主要来源。

### 第三层：Agent 工作过程——“为完成任务做过什么”

保存对话、Run、工具事件、审批、检索记录和浏览器回执。它用于恢复工作和审计，不自动变成知识。网页搜索结果、模型草稿、失败尝试和闲聊默认都停在这一层。

### 第四层：长期记忆——“以后别的项目也值得复用什么”

问津不会把对话或模型回答自动写入外部长期记忆库。程序先建立项目内“记忆候选”，并要求稳定来源 ID；候选经项目内批准后，还必须在“记忆”页由用户再次明确提升，才会在已配置的 `historical-memory` 或 `codex-memory` 的 `90_INBOX` 中建立一张 `draft` 卡片。问津不复制聊天全文、OCR草稿或来源文件。

适合提升的内容包括：

- 经多份材料验证、以后可复用的史学判断；
- 明确记录了检索边界的阴性结果；
- 用户批准的研究方法或工作偏好；
- 多篇样本支持的写作画像；
- 已验证的版本关系、地名异名或术语规范。

不应进入长期记忆的内容包括：

- 普通聊天和临时灵感；
- 单次模型回答；
- 未核 OCR 和未核翻译；
- 只有网址、摘要或搜索片段的线索；
- 被拒绝的研究方案；
- API 密钥、Cookie、账号信息和受限数据库凭据；
- 可以直接从项目数据库恢复的大段重复内容。

如果不确定是否值得长期保存，宁可留在项目候选区，不要提升。

## 十一、版本、备份和撤回

软件中的三种“版本”不要混淆：

1. **文件版本**：某个 PDF、DOCX 的精确字节版本；
2. **研究对象版本**：页面修复、研究计划、冻结、稿件修订；
3. **软件版本**：程序包版本和数据库 schema 版本。

文章工作台的“版本”页当前只列出结构化稿件修订、文本指纹和导入/导出保真回执，**不显示旧版全文，也还没有“设为当前版本”或一键回退按钮**。需要恢复时，应从先前导出的 Markdown/DOCX 或完整备份重新导入为新修订；不要直接改 SQLite 数据库。拒绝写作提案不会改变当前正文；批准、同步或手工保存才会产生新修订。编辑区目前也没有自动保存，切换项目或关闭窗口前应点击“保存新修订”。

项目数据默认保存在用户应用数据目录。桌面版启动时会在完整项目发生变化后建立SQLite在线备份；“AI 与 Agent—当前状态”还可以立即备份，并把某份备份恢复为新的项目副本。恢复不会覆盖当前项目。它不是无限期归档服务，重要节点仍应另外保存导出的Markdown/DOCX以及整个应用数据目录；密钥由Windows Credential Manager单独管理。

Git 用于撤回和比较程序代码，不替代研究项目内部的修订记录。不要用 Git 强行覆盖正在使用的项目数据库。

## 十二、常见问题

### 网页打不开

先确认本地服务仍在运行，再刷新。机构数据库可能禁止嵌入显示，此时使用“受控浏览器打开”；若提示 `agent-browser` 不可用，就到“技能与插件”确认程序集成，或改用“普通浏览器打开”。由用户完成登录和下载，再把取得文件导入图书馆。

### 模型没有反应

检查项目设置中对应角色是否显示可用；确认模型名、接口地址和密钥；本地 Ollama 需确认服务已启动。程序不会从不可用模型自动切换到其他付费模型。

### 运行提示“模型操作格式错误”或模型把工具文字直接说出来

工作台会自动尝试一次更短的格式重试。仍失败时，本轮不会伪装成成功；重新发送更小、更明确的任务。研究产物若已保存，界面会单独说明“产物已保存、最终回复失败”。

### 提示 `database locked`

本地数据库正被另一项写入占用。等待当前导入、盘点、写作或审批结束后再试；如果持续出现，关闭重复打开的工作台窗口。不要同时用外部 SQLite 工具写项目数据库。

### OCR 看起来很流畅，但原页不是这样

拒绝提案。流畅不等于准确。正文、数字、人名、地名或页码有误时，该页不能作为证据使用。

### 为什么检索结果不能直接引用

检索结果只证明数据库返回了一个条目。只有取得全文、确认版本、回到原页并完成人工证据资格检查后，才可以引用。

### 为什么导出稿显示 BLOCKED

查看导出警告。常见原因是作者信息未填、来源元数据未人工核验、原书页缺失、注释仍是候选或模板版本需重新核对。BLOCKED 是保护，不是程序故障。

### 为什么选区返修不能开始

常见原因是正文与批准章节尚未同步、选区跨越不连续内容、同样文字在本节重复出现、只选了部分表格，或已有待审提案未处理。先保存或同步正文，扩大为唯一且连续的选区，并批准或拒绝旧提案。

### 为什么阅读任务一直是 running 或 needs_repair

建立任务不等于读完。`running` 通常表示还有来源或可用页未形成札记；`needs_repair` 表示全文任务覆盖了现有可用页，但来源仍有阻断页。回到原页修复后，再让 Agent 继续有界阅读。

### 为什么图书馆候选不能勾选

不支持格式、读取失败、内容未变化和某些仅作提示的候选不能批准。DOC、EPUB、CAJ 和图片当前只登记在盘点收据中；应保留原件并准备受支持的 PDF、DOCX、Markdown 或 TXT 工作版本。

### 能否让 Agent 自动把所有研究内容记住

不建议，也不允许默认这样做。可靠的长期记忆应少而精，带来源、状态和提升理由。项目完整过程已经保存在项目内，不需要复制成另一堆难以维护的“记忆”。

## 十三、推荐的日常工作顺序

```text
建立研究者基线
→ 导入并验收材料
→ 修复页面和印刷页关系
→ 建立逐事件表
→ 有界补充检索
→ 核回原页并形成证据
→ 连接主张与反证
→ 人工批准冻结
→ 分节写作
→ 期刊导出预览
→ 多角色评审
→ Word 终校
→ 作者补全投稿信息
```

如果中途发现来源错误，应回退到页面或证据层修正，不要只在成稿中把句子改得更含糊。系统的价值就在于每个结论都能回到材料、每次修改都能找到版本、每个自动动作都不能越过人的最终决定。
